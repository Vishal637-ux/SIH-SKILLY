# SKILLY — Module 02: Authentication

## 1. Module Overview

**Module Name:** Authentication

**Purpose:**  
The Authentication module manages user account access for SKILLY. It provides registration, login, authentication and role-based access entry for platform users.

This module works as the access-control entry point before users enter their respective role-based areas.

## 4. Registration

Allows a new user to create a SKILLY account.

### Registration Flow

```text
Visitor
   ↓
Register
   ↓
Select User Role
   ↓
Enter Required Details
   ↓
Validate Details
   ↓
Create Account
   ↓
Account Ready for Login
```

### User Role Selection

The user selects the appropriate role during registration:

- Student
- College / TPO
- Teacher / Trainer
- Industry / Company
- Alumni / Mentor

> Exact registration fields for each role will be defined when the respective role module is implemented.

---

Allows an authenticated user to end their current session.

```text
       ↓
     Logout
       ↓

       ↓

```

---

## 7. Authentication

The system verifies that the user is a registered and authorized account holder.

### High-Level Process

```text
Credentials
    ↓
Authentication Service
    ↓
User Verification
    ↓
Account Status Check
    ↓
Authentication Success
```

The backend is responsible for actual authentication and authorization checks.

---

## 8. Role-Based Access

After authentication, the system identifies the user's role and provides access to the appropriate platform area.

### Example

```text
Login
  ↓
Role = STUDENT
  ↓
Student Area

Login
  ↓
Role = TPO
  ↓
College / TPO Area

Login
  ↓
Role = INDUSTRY
  ↓
Industry Area
```

### Basic Role Access

| Role | Main Area |
|---|---|
| Student | Student |
| College / TPO | College / TPO |
| Teacher / Trainer | Teacher / Trainer |
| Industry / Company | Industry / Company |
| Alumni / Mentor | Alumni / Mentor |

---

## 9. Account Status

Authentication should consider the account's current status.

Possible states:

```text
Account
│
├── Active
├── Inactive
└── Verification Required
```

An inactive or unauthorized account should not receive normal authenticated access.

---

## 10. Security

The Authentication module should follow the security architecture defined for SKILLY.

### Security Areas

- Password hashing
- JWT-based authentication
- Role-Based Access Control (RBAC)
- API authorization
- HTTPS / TLS
- Input validation
- Secure credential handling

### Security Flow

```text
User
 ↓
Login
 ↓
Credential Verification
 ↓
JWT Authentication
 ↓
Role Verification
 ↓
Authorization Check
 ↓
Protected Resource
```

> Frontend route protection is only a user-interface layer. Backend authorization must enforce access control.
